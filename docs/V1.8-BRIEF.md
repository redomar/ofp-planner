# 1.8 / 1.9 brief for the implementing agent

Read `docs/HANDOVER.md` first (workflow, verification, no AI attribution, semver). This file is the
spec for what is left of the 1.8 redesign and for 1.9. Written 2026-11-10.

## Where the design lives

Option sheets the owner reviewed, outside the repo: `../ofp-planner-previews/v1.8-direction/`
(`01`–`07` PNG, the same as pages in `live/index.html`, sources in `src/`). Sheet ids below (P2, S1,
F0+ …) refer to labels on those sheets. Look at the sheet before building a part.

Principles agreed: one job per screen; say it once; a flight is one object (the pass); everything
shown is real data; motion only when something changed; show the result, not the options; detail on
request; keep the paper look (tokens, type, AA contrast, no layout shift). The owner wants liked
options shipped as Settings choices with a default, not one winner.

## 1.9: gate screen in flight (sheets 02, 05, 07)

- Views of the same gate URL: full G1 (steps continue to the arrival gate), map G3, frame G3a (16:9
  transparent window for the game capture), map-with-window G3c, overlays strip G4, card/pill G5,
  map corner G3b. G2 is parked. Keep all of them.
- Flow (sheet 07, owner confirmed): **one browser source**, `view=auto`. The aircraft sets the stage
  (getting ready → push-back/taxi → flying → arrived); the OBS scene name sets the view (OBS
  `obsSceneChanged` / `getCurrentScene`, needs the source's Page permissions: verify in the owner's
  OBS). Fixed `&view=` URLs are the fallback. A Stream panel on Board → Gate screen sets it up; a
  rehearse strip plays the flight and can hold a stage.
- Pre-flight shows only real steps (Boarding, Doors closed, Pushback): no invented final-call or
  gate-closed times. Phase rules: table on sheet 05 (proposed, to tune on the sim PC).
- Feed order: OFP Link .exe (SimConnect, MSFS 2024, same PC as OBS) → SayIntentions (owner will give
  API access later; they fly 60–70 % there) → VATSIM feed (`data.vatsim.net/v3/vatsim-data.json`,
  CORS *, 15 s) → clock only (today). One message shape for every feed.
- OFP Link ideas: sends raw facts (phase rules stay in the web page), relays controller ⇄ OBS
  source, records each flight (replay for testing on a Mac, Logbook OUT/OFF/ON/IN and landing rate),
  listens on localhost only. It cannot be built or tested on the owner's Mac: develop the screen
  against a recorded flight.

## Things learnt building branch 1

- Class names already taken globally: `.sub`, `.chip`, `.status`, `.obs`, `.week`, `.strip`. Prefix
  new ones (`bp-` is the pass).
- `pnpm verify` reads `out/`: never rebuild while it runs. A full run takes about 8 minutes; run it
  in the background. `VERIFY_ONLY="boarding pass"` runs the two pass sections.
- Contexts made outside `open()` in verify need `SEED` (example airframe + layout-shift counter). The
  local build bakes the owner's own airframe from `.env.local`: never let it into a screenshot.
- Short animations are over before a check can look: record them as they start (see the unfold check).
- A global reduced-motion rule sets transitions to about 0 s (`1e-06s`), not `none`.
- Container queries: `.rh` collapses its three columns at ≤ 400 px; `.fcard-body` is the `card`
  container that moves the side stub under the pass at ≤ 400 px.

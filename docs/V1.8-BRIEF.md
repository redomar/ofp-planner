spec for what is left of the 1.8 redesign and for 1.9. Written 2026-11-10.

## Where the design lives

Option sheets the owner reviewed, outside the repo: `../ofp-planner-previews/v1.8-direction/`
(`01`–`07` PNG, the same as pages in `live/index.html`, sources in `src/`). Sheet ids below (P2, S1,
F0+ …) refer to labels on those sheets. Look at the sheet before building a part.

Principles agreed: one job per screen; say it once; a flight is one object (the pass); everything
shown is real data; motion only when something changed; show the result, not the options; detail on
request; keep the paper look (tokens, type, AA contrast, no layout shift). The owner wants liked
options shipped as Settings choices with a default, not one winner.

## Things learnt building branch 1

- Class names already taken globally: `.sub`, `.chip`, `.status`, `.obs`, `.week`, `.strip`. Prefix
  new ones (`bp-` is the pass).
- `pnpm verify` reads `out/`: never rebuild while it runs. A full run takes about 8 minutes; run it
  in the background. `VERIFY_ONLY="boarding pass"` runs the two pass sections.
- Contexts made outside `open()` in verify need `SEED` (example airframe + layout-shift counter). The
  local build bakes the owner's own airframe from `.env.local`: never let it into a screenshot.
- Short animations are over before a check can look: record them as they start (see the unfold check).
- A global reduced-motion rule sets transitions to about 0 s (`1e-06s`), not `none`.
- Container queries: `.rh` collapses its three columns at ≤ 400 px; `.fcard-body` is the `card`
  container that moves the side stub under the pass at ≤ 400 px.
